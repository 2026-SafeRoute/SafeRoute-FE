# 데스크톱 반응형 레이아웃

지원 범위는 viewport 1024px 이상이다. 이슈에 명시된 값이지만, 사용자 화면 분포나 사용성 테스트로 최적 하한이 입증된 것은 아니다. 모바일 사용을 권장하지 않는 제품에서 데스크톱 전용 레이아웃의 최소 지원 폭을 정해야 하므로 1024px을 **검증할 시작 하한**으로 둔다. 1024px 미만이 기술적으로 불가능하거나 모든 레이아웃의 CSS 전환점이 1024px이라는 뜻은 아니다.

## 기준

1024px은 임의의 기기 규격이 아니라 다음 세 가지를 함께 고려한 출발점이다.

1. 이 프로젝트의 펼친 사이드바 240px, 최소 페이지 좌우 여백 32px, 도면 카드 기본 폭 360px 두 장과 간격 16px을 합하면 약 1008px이 필요하다. 1024px에서는 기본 크기 카드 두 장을 배치할 여유가 약 16px 남는다. 이는 도면 목록에 대한 폭 계산일 뿐, 모든 페이지가 1024px에서 다단으로 보여야 한다는 뜻은 아니다.
2. [Tailwind CSS 공식 문서](https://tailwindcss.com/docs/responsive-design)는 `lg`의 시작점을 1024px로 둔다. 반면 [Bootstrap 공식 문서](https://getbootstrap.com/docs/5.3/layout/breakpoints/)의 `lg`는 992px이므로, 업계에 단일한 '데스크톱 최소 폭' 표준이 있는 것은 아니다. 1024px은 위의 제품 내 폭 계산을 충족하면서 널리 쓰이는 검증 지점이라는 참고 근거로만 사용한다.
3. [MDN의 미디어 쿼리 가이드](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/CSS_layout/Media_queries)는 기기 종류보다 콘텐츠가 깨지는 지점에서 레이아웃을 전환하라고 권장한다. 따라서 1024px은 지원 범위의 하한이고, 실제 카드·패널 전환점은 본문 너비를 기준으로 따로 정한다.

이 하한은 접근성 준수를 보증하지 않는다. [WCAG 2.2 Reflow 설명](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)은 훨씬 좁은 CSS 픽셀 너비에서의 재배치와 2차원 콘텐츠의 예외를 다룬다. 1024px 미만을 이번 작업 범위에서 제외하는 제품 결정과 WCAG 적합성은 별도로 평가해야 한다.

viewport 1024/1280/1440을 모든 컴포넌트의 전환점으로 쓰지 않는다. 전역 여백만 viewport 미디어 쿼리로 바꾸고, 패널은 실제 본문 너비에 따라 `@container`로 전환한다. 카드 목록은 `auto-fit` + `minmax(min(100%, 최소 카드 너비), 1fr)`로 공간이 허락하는 열 수를 자동 결정한다. 사이드바 접기 상태에서도 동일한 규칙이 작동한다. `@container`의 기준 폭은 페이지 컨테이너의 좌우 패딩을 포함한다.

| 위치                                  | 토큰·패턴                     | 용도                                                                                                         |
| ------------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `src/shared/styles/global.css.ts`     | `vars.layout`                 | 사이드바 폭, 페이지 좌우 여백(32/24/16px), 패널 간격, 콘텐츠 최대 폭(1600px)                                 |
| `src/shared/styles/responsive.css.ts` | `pageContent`                 | 공통 본문 폭·여백·inline-size 컨테이너                                                                       |
| 같은 파일                             | `contentBreakpoints`          | 본문 컨테이너 폭 800/900/960/1120/1400px: 카드·패널이 실제로 비좁아지는 지점별 전환점 (`html` 10px/rem 기준) |
| 같은 파일                             | `interactivePanelBreakpoints` | 실제 작업 영역을 관측해 패널 기본 상태를 정하는 기준(도면 상세 1300px)                                       |
| 같은 파일                             | `cardGrid`, `twoColumnGrid`   | 카드 최소 폭 240px의 자동 그리드 / 800px 이하에서 한 열이 되는 최대 두 열 그리드                             |

새 페이지는 최상위 페이지 요소에 `style([pageContent, { ... }])`를 합성하고, 고유한 세로 여백만 `paddingBlock`으로 지정한다. 자식 컴포넌트가 본문 폭에 따라 바뀌어야 한다면 공유 전환점으로 `@container`를 쓰되, 그리드가 자동으로 해결되는 경우에는 쿼리를 추가하지 않는다. 도면 편집 캔버스처럼 화면 전체가 작업 영역인 뷰에는 최대 폭을 강제하지 않는다.

표는 정보 열을 지나치게 줄이거나 잘라내지 말고 해당 카드 안에서만 가로 스크롤한다. 모달은 뷰포트 기준 최대 너비/높이를 유지하고, 포털 드롭다운은 뷰포트 좌우 경계 안으로 배치한다.

## 화면별 결정

- 홈: 요약 지표가 3+1로 남는 구간은 2×2로 묶는다. 최근 기록과 예정 훈련은 본문 컨테이너가 900px보다 넓으면 나란히 두고, 그 이하에서는 예정 훈련을 먼저 배치한다. 나란히 놓였을 때 최근 기록 표의 열은 카드 내부에서만 가로 스크롤한다. 예정 훈련은 파란 정보 패널과 세로 흐름을 유지하며, 훈련이 없으면 실행 버튼을 숨긴다. 실행·예약된 세션이 없고 준비완료 시나리오가 있으면 준비 대상으로 표시하고 시나리오 설정으로 이동한다.
- 시나리오: 설정/조작 패널은 본문이 비좁아질 때 한 열로 바꾼다. 시작·수정 액션의 아래 여백은 해당 패널에만 적용한다.
- 건물·도면·훈련 분석·보고서: 일반 카드 목록은 최소 카드 폭을 지키며 자동으로 열 수를 줄인다. 도면 목록 카드는 항목이 적어도 가로로 늘어나지 않도록 360px 폭을 기본으로 하고, 공간이 부족할 때만 줄인다. 카메라 프레임 화면의 3단 패널은 본문 폭에 따라 2단, 1단으로 전환한다. 보고서 제목과 메타 정보는 위쪽에 정렬하고, 메타 정보는 가능한 열 수로 줄바꿈한다.
- 도면 상세: 좌측 층 탐색(280px)과 우측 장비 목록(320px)을 모두 둔 채 캔버스를 더 줄이지 않는다. 상세 작업 영역이 1300px 미만이면 장비 목록을 48px 레일로 접어 시작하고, 버튼으로 언제든 다시 펼칠 수 있다. 사용자가 직접 선택한 열림/접힘 상태는 크기가 바뀌어도 유지하며, 도면에서 다른 장비·구역을 선택하면 목록을 열어 해당 항목으로 이동한다.
- 공통 UI: 헤더는 폭이 부족할 때 줄바꿈하고, 드롭다운 패널은 트리거를 기준으로 열되 뷰포트 경계에서 위치와 너비를 보정한다.

## 검증

자동 검증은 `pnpm lint`, `pnpm build`, `pnpm format:check`로 한다. 수동 검증에서는 1024, 1280, 1366, 1440, 1920px에서 사이드바 펼침/접힘 각각 홈, 건물, 도면 목록·편집, 시나리오 목록·설정, 훈련 분석·카메라·프레임, 보고서를 확인한다. 카드 열 수와 패널 순서뿐 아니라 표의 내부 스크롤, 긴 이름, 모달/드롭다운 경계, 브라우저 `document.documentElement.scrollWidth > innerWidth` 여부를 확인한다. 도면 상세에서는 장비 목록의 기본 접힘, 수동 열림/접힘, 사이드바 전환 뒤 상태 유지, 도면 항목 선택 시 자동 열림과 목록 포커스를 함께 확인한다. 데이터가 없거나 인증되지 않은 상태는 실데이터 화면의 검증으로 간주하지 않는다. 이 문서는 수동 검증 완료를 주장하지 않는다.

참고: [MDN 컨테이너 쿼리](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_queries), [MDN Grid auto-fit](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/CSS_layout/Grids).
